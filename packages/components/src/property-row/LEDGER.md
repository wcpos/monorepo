# Behaviour ledger: `property-row`

Created 2026-10-25 for the property-rows grammar Paul chose after five boards (`~/Projects/wcpos-handoffs/2026-10-25-property-rows-system.html`, `2026-10-25-property-rows-every-form.html`). Numbers are assigned once and never reused; every line keeps its evidence.

**Job:** Show a record or a settings page as a list of facts, one row per fact (key · value · verb), with a record's absent facts offered as add buttons at the bottom.

**Not its job:** deciding which facts are asked for or present (`useFieldPresence` in core and the record's own field list), saving (the form's autosave). `SettingsRow` and `LockedRow` were deleted into this row on 2026-10-28 (card 5, second half); settings LEDGER lines 2 and 4 moved here as lines 9 and 12.

**Base:** React Native `View`, `Text` / `TextClassContext`, `Button`, `DocsLink`, `Switch`, and from `form/`: `FormItem`, `useSavedName`, `SavedMark`.

## Lines

1. Rows have no dividers; they separate by rhythm alone, as settings rows do (settings LEDGER line 1) — evidence: the system board, "no divider between rows"; test "renders the key, the value and the trailing slot, with no divider".
2. The key is `md:w-32` (128) in muted `text-sm`; the value is `text-base` foreground, set through `TextClassContext` — evidence: the system board's "one new ladder role" table; same test.
3. On `md+` key, value and trailing share one 44 line (`min-h-ctl`); under `md` the key stacks above the value and the trailing slot stays on the key's line, out of flow (the SettingsRow rule, settings LEDGER line 4) — evidence: the system board's implementing rules, "Phone: the key stacks above the value under md".
4. An open compound's parts are rows with `indent`: the key moves in one gutter (`pl-4`) — evidence: the board's "Compound, open: its parts are rows, indented one gutter"; test "pads the key of a part…".
5. Add buttons are `Button variant="outline" size="sm" leftIcon="plus"` (36), wrapping with `gap-2`, never Chips: a Chip is a selectable state and these are actions (CODING_STANDARDS § Chips, badges and switches) — evidence: the system board, "Add row"; test "an add is a 36-tall outline Button…".
6. Verbs are `Button variant="link" size="sm"` (primary, 13 medium), never a chevron — evidence: the board's verb vocabulary; test "a verb is a small link Button in primary ink".
7. An empty asked-for value reads as a placeholder in muted ink (`PROPERTY_PLACEHOLDER_CLASS`), shared with `EditableField`'s placeholder so the two never disagree — evidence: the board's "Asked but empty: a placeholder verb, no box".
8. The row reads the form's Saved name: `name` (the field or fields it holds, `id` by default) decides whether the mark shows, and the mark takes the verb's place, never beside it; a trailing `control` (a Switch) comes after it, so a mark arriving never moves the control. Nine wrappers (PrinterRow, OrderRow, CartLineRow, CouponRow, CatalogueRow, the customer and address rows, tax IDs, custom fields) each re-derived this; a list (tax IDs, custom fields) names its field on its first row only — evidence: card 5 of the 2026-10-28 component-library review; test "the row owns the trailing slot".
9. The row is the form item: the list's `prefix` (or the row's own) and `id` give the testID `<prefix>-row-<id>` and the item id `<prefix>-<id>` (minted without them), the key is `<item>-form-item`, a label-less control in the row adopts it, and pressing the key presses that control (focus, toggle). It needs no react-hook-form provider, so the customer-display page's rows render as the others (moved from settings LEDGER line 2) — evidence: tests "the row is the form item…", "pressing the key acts on the control it names".
10. Set elsewhere is locked (rule 6): the value, then where it is set and _Open ↗_ (`DocsLink`) when there is a link; a boolean value is a disabled switch, an empty one a dash. Used today by the order's payment, the customer's username and role, and a product's variations; and the settings pages' locked rows (replacing `LockedRow` and their "Set in WooCommerce, mirrored here" note line) — the orchestrator's pick, Paul to confirm; dropping Open is the one `DocsLink` line in the row — evidence: the property-rows system board, "Locked: value plus where it is set · Set in WooCommerce · Open ↗"; test "locked (rule 6)…".
11. A derived value (rule 5) reads in muted ink; its verb breaks the link — evidence: the board's "Derived: value in muted"; test "a derived value reads in muted ink".
12. The key column is the list's: 128 (`md:w-32`) in a dialog, `PropertyList wide` (every `SettingsSection`) 256 / 288 (`md:w-64 lg:w-72`) with the value in one 320 column (`md:max-w-80`), so a settings page's marks and switches line up in one trailing column (moved from settings LEDGER line 4, where they were `SettingsRow`'s) — evidence: the board's "the key column is w-32 in a dialog and md:w-64 lg:w-72 on a settings page"; test "the key column in …".
13. `stacked` puts the key above the value at every width with the trailing slot on the key's line: a value too big for the line keeps its Saved mark in the row instead of an absolutely placed one (the theme tiles, the icon sets, the scan sounds and the scan volume) — evidence: card 5 ("the saved mark is hand-placed at 5 offsets"); test "the key column in stacked".
14. `help` is one line under the key in the help rank — evidence: CODING_STANDARDS § Design 11 ("the help line says what happens at the till"); test "the key column in …".
15. A `compound` row (two or more controls in the value: a custom field's key and value) resets the item context for its value, so each control keeps its own name and message id; the row stays the item for its key — evidence: Codex P2 on #3011; test "a compound row keeps each control its own name and message".
16. A setting is this row (2026-10-28, card 5 second half): every settings page's rows are `PropertyRow`s in `SettingsSection`'s wide list, so a setting takes the record row's rhythm (44 tall, `py-1`) and its value column starts after the key; a switch is the row's `control`; nested settings are `indent`ed rows (rule 8), not a padded group — evidence: the property-rows board, "Settings › General — SettingsRow is this row"; tests `general.test.tsx`, `tax.test.tsx`, `theme.test.tsx`.
17. Under `md` the trailing slot sits on the key's line, out of flow, only while it is narrow (a Saved mark, a verb, a Switch); a locked row's provenance ("Set in WooCommerce · Open ↗") is words, so it wraps in flow under the value and never lies over a long key on a phone — evidence: Codex P2 on #3016; test "a locked row puts its provenance in flow…".
