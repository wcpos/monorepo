The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. **Job:** An anchored popover with a trigger, portal-backed content and animated presentation.

**Base:** `@rn-primitives/popover` through `anchor.tsx` (the popover family's anchored adapter, shared with the multi-select, combobox and tree combobox) and `AnchoredOverlay` (`lib/overlay.tsx`); no platform-suffixed files.

## Lines

1. Gives native portal wrappers full-screen bounds so Android accessibility does not prune visible content — evidence: `8278ba5598 2026-08-28 fix(components): popover-family portals were invisible to Android accessibility (#1623)`, PR #1623, issue #1614, code: "style={Platform.OS !== 'web' ? StyleSheet.absoluteFill : undefined}" in `packages/components/src/popover/index.tsx:46`.
2. Lets outside taps pass through the animation wrapper to the dismissing overlay — evidence: `8278ba5598 2026-08-28 fix(components): popover-family portals were invisible to Android accessibility (#1623)`, PR #1623, issue #1614, code: "pointerEvents=\"box-none\"" in `packages/components/src/popover/index.tsx:45`.
3. Pins entrance and exit fades to the shared 200 ms duration instead of the default exit duration — evidence: `89fe07768d 2026-09-11 feat(components): overlay batch 0 — motion constants, phone-sheet shell, panel dismissal, pinned footer (#1974)`, PR #1974, code: "exiting={FadeOut.duration(POPOVER_FADE_MS)}" in `packages/components/src/popover/index.tsx:44`.
4. Accepts left and right placement in its public `side` type — evidence: `08c70e8df1 2026-02-12 fix: update component types to support existing size and side values`, code: "side?: 'top' | 'bottom' | 'left' | 'right';" in `packages/components/src/popover/index.tsx:28`.
5. Consumes the outside press that dismisses the anchored web panel: a transparent full-screen layer behind the panel takes it, so the element underneath is never pressed (the phone sheet's scrim and native's full-screen `Overlay` already did this) — evidence: PR #2313 (a closing tap on the POS footer tax popover pressed the product tile under it), test `packages/components/src/popover/outside-press.test.tsx`, code: "outsidePress" in `packages/components/src/popover/index.tsx` (the shell passes it only when anchored) and "style={onOutsidePress ? OUTSIDE_PRESS_LAYER : undefined}" in `packages/components/src/lib/overlay.tsx`.
6. A press on a toast is not an outside interaction for the anchored panel: the toast's action runs and the popover stays open, as a dialog does (#2284) — evidence: PR #2313, test `packages/components/src/popover/outside-press.test.tsx`, code: "if (isToastTarget(event.target)) event.preventDefault();" in `packages/components/src/popover/index.tsx`.
7. The anchored panel is flat: `OVERLAY_PANEL.anchored` is `bg-card` with a hairline border and an 8 pt radius, no shadow; the dropdown menu, select, combobox, hover card and tooltip share it — evidence: decision 11 of the 2026-10-16 component-consistency board, CODING_STANDARDS § Design 7; the owner looks at it on dev-next before it is final; test "anchored" assertions in `lib/overlay.test.tsx`.
8. On web the phone sheet (`OverlaySheetPanel`, shared with the select, combobox and dropdown menu) mounts an untrapped Radix focus scope, `SheetFocusScope`: it has no primitive Content, so a modal dialog under it kept its focus trap and pulled every focus in the sheet back, and a form's keypad opened from a dialog never heard a physical key. The scope pauses the dialog's trap while the sheet is open and moves no focus itself (the shell still does) — evidence: Codex on wcpos/monorepo#2995 ("Give phone keypads a focus scope inside modal forms"); test `packages/components/src/lib/sheet-focus-scope.web.test.tsx`.
9. The phone-or-anchored decision is the shell's: `AnchoredOverlay` (`lib/overlay.tsx`) makes every popover, dropdown menu, select, multi-select, combobox and tree combobox the bottom sheet on a phone (`useIsPhone`, so a `DeviceScope` decides in a story) and the primitive's positioned panel elsewhere, with the panel skin, motion, dismiss, the inline gallery and the portal. A caller hands its primitive family (`OverlayAnchor`: portal, scrim, positioned Content), the anchored panel's size and the props its Content was given; a list's sheet scrolls the rows in a `menu` or `group` container. The six callers each wrote `useIsPhone → phone ? 'bottom' : 'anchored'` until then, and their per-primitive phone tests went with it — evidence: card 3 of the 2026-10-28 component-library review; test `lib/anchored-overlay.test.tsx`.
