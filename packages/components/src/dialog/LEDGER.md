# Behaviour ledger: `dialog` (formerly `v2/dialog`)

`v2/dialog` folded into this directory on 2026-10-16 (wcpos/monorepo#2604); read `v2/dialog` as `dialog`. Exceptions: a bare `dialog` N in the From sections, "twin of `dialog` N", and every `packages/components/src/dialog/…` evidence path in those sections mean the deleted v1 component (`dialog.LEDGER.md`), not this one.

2026-10-16: the one overlay system. `modal` and `dialog` v1 are deleted (wcpos/monorepo#2603); their ledgers sit beside this one as `modal.LEDGER.md` and `dialog.LEDGER.md`.

Seeded 2026-09-22 by wcpos/roadmap#374 from `dialog/LEDGER.md` and `modal/LEDGER.md` (wcpos/roadmap#345), the component map (wcpos/roadmap#291) and the platform-split page (wcpos/roadmap#290). Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** The one overlay for a task that takes the cashier away from the surface: a centred dialog, a side panel, a phone page, or a sheet; trigger-opened or route-opened on one root.

**Base:** `@rn-primitives/dialog`, `@rn-primitives/slot`, `expo-router`, `react-native`, `lib/overlay` (the shell owns Reanimated, safe-area and the keyboard wrapper), `lib/device`.

## `v2/dialog`

1. Under the phone width a side panel renders as a page; a centred dialog and a sheet never split — evidence: platform split (wcpos/roadmap#290) §2; the component map §4.
2. One root serves a trigger-opened and a route-opened dialog; a route dialog closes by navigating back unless the caller supplies `onClose` — evidence: the component map §7a; `modal` line 3 as origin.
3. The ×, the scrim, Escape, the hardware back and `close()` are one path through `onOpenChange(false)` — evidence: the component map §7a; `.claude/rules/design.mdc` §3.
4. The overlay plumbing lives in `lib/overlay` and the component reads no platform — evidence: platform split §4.
5. The close control carries an accessible name the caller may override (default Close) — evidence: `page-bar` line 5 as precedent; Codex review on wcpos/monorepo#2188.
6. The scrim is the theme's `scrim` token, never a black alpha — evidence: the token sheet (wcpos/roadmap#357); `.claude/rules/design.mdc` §7.
7. The generated close control is sized to the control token, because an icon plus its padding is under the pointer floor — evidence: `page-bar` line 6 as precedent; Codex review on wcpos/monorepo#2200.
8. A press or focus inside the toaster is not an outside interaction: a toast's action can belong to the dialog under it (the register panel's Undo), and pressing it must not dismiss that dialog — evidence: #2284 cause E, trace of run 36690251788 shard 1 (`register-session.spec.ts:77`), code: "if (isToastTarget(event.target)) event.preventDefault();" in `v2/dialog/index.tsx` `DialogPanel`.
9. On web a panel slides in solid: the scrim fades its colour (`overlay-in` animates `background-color`), not its own opacity, because the panel is the scrim's child and inherited the fade — evidence: filmed frame by frame 2026-10-02 (order sheet, cart settings, products settings): the products showed through the panel for the whole slide.
10. On web a closing dialog plays its exit: the panel slides back into its edge on `EASE_EXIT` while the scrim fades, and the leaving scrim takes no presses. `DialogContent` no longer returns null when closed on web (`OVERLAY_EXIT_MOUNTED`), and the Radix wrappers around the scrim and the panel hold for the exit (`EXIT_MARK`, `overlay-hold` in `global.css`): Radix waits on its OWN wrapper's animation before unmounting, and unanimated they removed the panel on the first frame — evidence: filmed 2026-10-02, a closed panel was gone one frame after Escape; probed: the scrim now stays ~225 ms; test 1 mirrors Radix presence in its mock. Native is unchanged: its primitives unmount at once and Reanimated plays `exiting` (now on `EASE_EXIT` for the sliding presentations; not run on a device).
11. On web the shell's scrim sizes Radix's `role="dialog"` wrapper as the panel's box (`SCRIM_WRAPPER`: a row flex box stretched on the scrim's cross axis, capped at the scrim, `w-full` for the page, `max-h-[92%]` for the sheet) and never flattens it to `display: contents` — `dialog` line 13: flattened, Chromium starts no native HTML5 drag inside the panel (the column reorder in every settings panel, 2026-10-12). The bottom panel's cap moved from the panel to the wrapper. Pinned by `lib/overlay/index.test.tsx`.
12. The phone sheet panel (`OVERLAY_PANEL.bottom`, `[data-sheet]`) keeps its own `max-h-[92%]` on web, where `SCRIM_WRAPPER` skips it and nothing else caps it; native caps the sheet on the shell's wrappers and the panel takes `max-h-full` — evidence: independent review of wcpos/monorepo#2529 (the native-only cap move had left web sheets uncapped), pinned by `lib/overlay/index.test.tsx` and `lib/overlay/index.native.test.tsx`.
13. Only a `blocking` shell (a confirmation) takes the scrim's touches away, and only on native, so a dialog's scrim press dismisses again; a bottom dialog pads the bottom inset itself through `useSheetInset(16)` and its native panel takes `max-h-full` under the shell wrapper's cap — evidence: independent review of wcpos/monorepo#2529 (the shell had set `pointerEvents: 'none'` on every scrim without a dismiss prop, killing every v2 dialog's scrim press); tests "takes no touches on a blocking scrim (a confirmation)", "pads only a native bottom sheet with the inset (%s)" in `lib/overlay/index.native.test.tsx` and test 14 here.
14. A native bottom sheet's keyboard wrapper is on only while the keyboard is visible (`useKeyboardState`), with no vertical offset: hidden, it would pad the sheet off the screen edge; visible, it pushes a searchable picker (combobox, tree-combobox open the keyboard on mount) above the keyboard.
