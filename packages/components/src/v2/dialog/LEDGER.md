# Behaviour ledger: `v2/dialog`

Seeded 2026-09-22 by wcpos/roadmap#374 from `dialog/LEDGER.md` and `modal/LEDGER.md` (wcpos/roadmap#345), the component map (wcpos/roadmap#291) and the platform-split page (wcpos/roadmap#290). Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** The one overlay for a task that takes the cashier away from the surface: a centred dialog, a side panel, a phone page, or a sheet; trigger-opened or route-opened on one root.

**Base:** `@rn-primitives/dialog`, `@rn-primitives/slot`, `expo-router`, `react-native`, `lib/overlay` (the shell owns Reanimated, safe-area and the keyboard wrapper), `lib/device`.

## `v2/dialog`

1. Under the phone width a side panel renders as a page; a centred dialog and a sheet never split — evidence: platform split (wcpos/roadmap#290) §2; the component map §4.
2. One root serves a trigger-opened and a route-opened dialog; a route dialog closes by navigating back unless the caller supplies `onClose` — evidence: the component map §7a; `modal` line 3 as origin.
3. The ×, the scrim, Escape, the hardware back and `close()` are one path through `onOpenChange(false)` — evidence: the component map §7a; `.claude/rules/design.mdc` §3.
4. The overlay plumbing lives in `lib/overlay.tsx` and the component reads no platform — evidence: platform split §4.
5. The close control carries an accessible name the caller may override (default Close) — evidence: `page-bar` line 5 as precedent; Codex review on wcpos/monorepo#2188.
6. The scrim is the theme's `scrim` token, never a black alpha — evidence: the token sheet (wcpos/roadmap#357); `.claude/rules/design.mdc` §7.
7. The generated close control is sized to the control token, because an icon plus its padding is under the pointer floor — evidence: `page-bar` line 6 as precedent; Codex review on wcpos/monorepo#2200.
