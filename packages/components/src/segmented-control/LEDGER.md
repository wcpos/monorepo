# Behaviour ledger: `segmented-control`

Seeded 2026-09-21 by wcpos/roadmap#360 from the component map (wcpos/roadmap#291), the register sign-off (wcpos/roadmap#287) and the scale page (wcpos/roadmap#289). Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** One single-select value picker of two to four segments.

**Base:** `react-native` View and Pressable; `Text` and `Icon`.

## Lines

1. The selected segment cannot be pressed off; a picker is never empty — evidence: component map §5 and §7a (one value picker).
2. The group is one Tab stop with arrow keys between segments — evidence: the ARIA radiogroup pattern; map §8 F8 (Tab order, no roving tabindex in navigation).
3. Two to four segments, enforced by the type — evidence: map §5.
4. The disabled state is always an explicit boolean — evidence: `button` ledger line 1 as origin (`c99855da17`); Codex review on wcpos/monorepo#2189.
5. The one few-way switch (2026-10-17, Phase D): `ToggleGroup` was removed and its form use is `FormSegmentedControl`; a few-way view or value switch is a SegmentedControl, sections are `Tabs`, and a longer list of choices (variation options) is a row of `Chip`s — evidence: ruling `ruling-design-system-decisions-2026-10-16` decision 10; CODING_STANDARDS § Design "Chips, badges and switches".
6. A label that wraps grows the control (`min-h-ctl`, segments `py-1.5`, labels shrink and centre) instead of being clipped by the rounded root; one-line labels keep it at 44. The one tab stop is never a disabled segment (the selected one if enabled, else the first enabled; none when all are disabled), and the `ref` handle's `focus()` lands on it, which is what a form field's focus-on-error calls — evidence: Codex review on wcpos/monorepo#2628 (the coupon discount type at phone width; `FormSegmentedControl` disabled and focus-on-error); `index.test.tsx`.
7. One ink per segment through `TextClassContext`: `text-selected-foreground` selected (was `text-foreground` until 2026-11-08, line 8), `text-muted-foreground` not; the label names no colour and keeps one weight, `font-medium`, in both states (it was `font-semibold` selected until 2026-11-08: selection never changes weight, ruling 2026-10-30), and the glyph names no colour (it was always `text-foreground`, the one outlier the sweep found) — evidence: 2026-10-29 sweep; tests: "one ink: selected and unselected segments give every glyph and word the same ink", "the selected segment is the tinted block, at the one weight both states share".
8. The selected segment is the tinted block, `bg-selected` (and `web:hover:bg-selected`, so a pointer resting on it keeps the tint), with its ink `text-selected-foreground` (line 7), the selection language of a Chip's `on`; it replaced `bg-muted`, the pre-October language. The hairline between segments (`border-l`) and the root border stay — evidence: Paul's 2026-10-29 light-theme ruling (selected states are the `--selected` pair); test "the selected segment is the tinted block, at the one weight both states share".
9. Segments are `flex-1` by default: equal shares of a definite width, which is what a column gives (every `FormSegmentedControl`, the add-discount sheet, the refund form, the theme page stretch to the column). `hug` makes them `web:flex-1 native:grow-0 native:shrink` (basis auto: content width, shrinking to truncate), so in a row parent the control takes only its labels' width on native; web already hugs with `flex-1`. The control cannot decide alone: Yoga gives an auto-width container with growing children the whole row (`native:grow native:shrink` did not hug, measured on the iPad), and `amount-unit-toggle.tsx` keeps its own `w-28 shrink-0`. The callers in a row say `hug`: the checkout column's header, the tender's non-compact header (its compact row keeps `flex-1`), the where-sold card head and the printer setup's paper row — evidence: owner, iPad, 2026-11-08: "On the Tender page, the Payments|Legacy segmented button fills the width and hides the close cross", and with the close hidden a cashier cannot leave a checkout on a tablet; tests "segments are equal on web and hug their content on native (hug=%s)" and `checkout-column.test.tsx` "the header's segmented control hugs, so the close stays on screen".
