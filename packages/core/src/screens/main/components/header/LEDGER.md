# Behaviour ledger: `components/header`

Seeded 2026-09-18 from `.claude/research/2026-09-18-composed-behaviour-ledger.md` on `research/composed-ledger` (wcpos/roadmap#341) by wcpos/roadmap#345. Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. **Job:** Provide responsive title chrome, connectivity status, user/store actions, upgrade notices, and notification controls.

**Composes:** `@wcpos/components/{alert-dialog,avatar,badge,button,dropdown-menu,error-boundary,hstack,icon,icon-button,lib/utils,loader,popover,portal,suspense,text,toast,tooltip,virtualized-list,vstack}`.

## Lines

1. Center titles against the viewport using measured asymmetric button widths, but give long titles the full available width and ellipsis — fixed padding cannot handle changing controls and store names — evidence: `547d1b0cab 2026-01-23 feat: smart header title truncation with measure-based centering` — platform: all.
2. Keep non-small titles transparent until centering measurements arrive; small screens show immediately without centering — prevents a visibly misplaced first frame — evidence: `4b9e6f5f15 2026-08-20 fix(core): header title measurements survive hidden screens; title hidden until measured`; matching first-paint and small-screen tests in `header-centering.test.tsx` — platform: all.
3. Ignore zero-width reports from hidden screens — `display:none` must not erase valid measurements and cause a title jump on every revisit — evidence: `4b9e6f5f15 2026-08-20 fix(core): header title measurements survive hidden screens; title hidden until measured` — platform: web/Electron.
4. Associate left-section measurements with their breakpoint and derive zero on large screens — a medium layout must not reuse an icon-only small measurement or paint before its menu label is measured — evidence: `f17d0a7736 2026-08-20 fix(core): require current header-left measurement`; breakpoint-transition tests in `header-centering.test.tsx` — platform: all.
5. Use light system-bar icons against the dark sidebar header — system chrome must remain legible across themes — evidence: “Status bar uses 'light' style (white icons) because sidebar is always dark” (`components/header/index.tsx:152`) — platform: iOS/Android.
6. Connectivity indicators remain presentational; transition logging/toasts belong to one app-level owner — visited drawer screens remain mounted and previously emitted duplicate notifications — evidence: `a4506f98ca 2026-08-04 fix(header): dedupe online-status toasts to a single app-level mount` (issue #929) — platform: all.
7. Avatar loading suspends only the image and displays initials meanwhile — a slow avatar must not blank the menu — evidence: “its own component behind a Suspense boundary that falls back to initials.” (`components/header/user-avatar.tsx:12`) — platform: all.
8. Subscribe to the rendered display name and reuse it for avatar initials — user renames previously never reached the header — evidence: `e544911176 2026-08-16 fix(ui): subscribe to the fields that are rendered, instead of reading them off the document (#1240)`; `user-menu.test.tsx`: “updates the header and the avatar initials when the name is changed” — platform: all.
9. Await store switching, show a blocking switching overlay, navigate only on success, and surface failure — failed hydration must not present a successful switch — evidence: `350e707d15 2026-07-30 feat(pos): transactional store switch — hydrate first, commit after, scope.switch, navigation (#876)` — platform: all.
10. Let Expo Router replace the web URL with the selected server store ID — refresh must reopen that store without corrupting router history — evidence: “clobbering Expo Router's own history state the way a manual” (`components/header/use-switch-store.ts:26`); `a22f31dafe 2026-07-31 fix(review): transactional engine scope switch + multi-db disposal marking (#882 round 1)` — platform: web.
11. Hold the store-list resource outside React’s retry lifecycle and give the submenu its own Suspense boundary — repeated pre-commit suspension must neither loop forever nor blank the surrounding route — evidence: `6b6040918b 2026-08-30 fix(core): keep every Suspense resource alive across a pre-commit retry` (issue #1707); subscription-count and menu-visibility tests in `user-menu.suspense.test.tsx` — platform: all.
12. Count unsent changes before confirming local-data deletion; unknown counts receive a worst-case warning rather than being treated as zero — reset can destroy sales never acknowledged by the server — evidence: `8856804928 2026-08-14 fix(app): stop the crash screen's "Try again" from wiping unsent sales (#1098)` — platform: all.
13. Schedule clearing before next hydration and reload instead of deleting beneath mounted providers — live RxDB handles must not point at destroyed databases — evidence: `6336210545 2026-08-19 fix: clear local data safely on native — schedule, reload, or freeze`; `user-menu.test.tsx`: “schedules the pre-hydration clear and reloads without touching the databases” — platform: all.
14. Freeze the register when a scheduled reset cannot restart the production app — sales made afterward would otherwise be deleted on relaunch — evidence: “anything sold after the confirm would be silently destroyed” (`components/header/user-menu.tsx:107–108`) — platform: iOS/Android.
15. If scheduling fails, native refuses destructive clearing; web falls back to direct clear plus reload — native has no guaranteed restart to recover destroyed handles, while restricted browser storage must not disable reset entirely — evidence: `6336210545 2026-08-19 fix: clear local data safely on native — schedule, reload, or freeze`; both branches named in `user-menu.test.tsx` — platform: all.
16. Notification consumers read session-owned state instead of bootstrapping Novu themselves — opening the panel must not reinitialize the client, socket, or initial fetch — evidence: `a1955c0204 2026-08-02 fix(notifications): hoist Novu bootstrap to a single session owner` (issue #911) — platform: all.
17. The bell subscribes only to notification summary state — notification-body/list churn must not rerender a badge whose count is unchanged — evidence: `b29701caa7 2026-08-16 perf(ui): split two contexts so badge consumers stop subscribing to list churn (#1242)` — platform: all.
18. Opening the bell marks notifications seen through the open-change handler; reading individual items remains separate — avoids effect-driven seen updates on unrelated renders — evidence: `b1b12f7b87 2026-01-19 refactor: replace useEffect with direct event handler in NotificationBell` — platform: all.
19. Constrain the notification popover and give its virtualized list a shrinking flex container — long notification lists must scroll inside the popover rather than overflow — evidence: `237bc1b6f2 2026-01-21 fix: notification panel overflow and VirtualizedList parentProps bug` — platform: all.
20. Keep the compact mark-all-read action touch-safe — smaller typography must not shrink its hit area — evidence: `b6f74171bd 2026-08-18 fix(ui): preserve compact action hit areas`; `notification-panel.test.tsx`: “keeps a touch-safe hit area on the compact mark-all-read action” — platform: all.
21. Notifications live in the drawer, with an optional label for expanded navigation — removing the POS title bar must not remove notification access — evidence: `89813429d6 2026-09-11 feat(pos): the register bar — no title bar on the POS, server register pointer, user sheet, switch store (roadmap#268)` — platform: all.
22. Choose an upgrade-message index once, but derive its text from the current translator — rerenders must not randomize copy, and language changes must still translate it — evidence: “Pick a random message index once on mount” and “The text itself is derived from `t` so it stays translated.” (`components/header/upgrade-notice.tsx:15–16`) — platform: all.
23. External menu/upgrade links use the shared external-URL handoff — Electron must open the system browser rather than mishandle direct linking — evidence: `372bebd5ba 2026-08-20 feat(ui): one source of truth for totals, DocsLink component, per-hour request estimate` — platform: all, especially Electron.
