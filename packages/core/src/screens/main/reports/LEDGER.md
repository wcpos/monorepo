## Lines

1. Sales initially requests completed orders for today, the current cashier and store, with an all-results limit — a report must aggregate the bounded set, not a browse page — evidence: [^query], `reports/index.tsx:152–169` — platform: all.
2. Re-key the Sales query provider when cashier/store changes; validate persisted sorting and otherwise use creation-date descending — prevents retained scope or unsupported settings governing the next report — evidence: [^query], `reports/index.tsx:52–76,164`; test names “re-initializes report filters when the selected store scope changes” and “rejects sort fields outside the orders surface” — platform: all.
3. Resolve default dates in store time; removing the date filter restores today rather than unbounding the report — evidence: [^timezone]; `reports/filter-bar.tsx:56`, “Reports must stay bounded to a date window; clearing restores today's window.” — platform: all.
4. Build report orders from engine payloads and attach the engine UUID for selection — avoids depending on the removed document-proxy representation — evidence: `f11f0b9987 2026-08-20 refactor(core): orders display sweep onto engine-native records (ADR 0028 stage H)` — platform: all.
5. Keep binding, selection and data in separate contexts, with no combined hook — binding-only consumers must not follow every order emission or checkbox change — evidence: `f0534f1075 2026-08-16 perf(reports): split the reports context three ways by change frequency (#1243)` — platform: all.
6. Obtain the stores Suspense resource outside React’s render lifecycle — rebuilding it on an uncommitted retry causes endless suspension — evidence: `reports/filter-bar.tsx:51–52`, “Held outside React on purpose — a resource rebuilt on each Suspense retry re-suspends forever.” — platform: all.
7. Give customer, cashier and store pills their own Suspense boundaries — an unresolved pill must not blank the route body — evidence: `reports/filter-bar.tsx:78–82`, “a pill still waiting for its records must never blank the screen around it”, naming #1707 — platform: all.
8. Resolve selected customer/cashier labels through engine lookups and request missing records; do not refresh a guest customer or invalid cashier ID — preserves meaningful filter labels without guest lookups — evidence: [^query]; `73f81fa5fb 2026-04-09 fix: skip guest lookup in reports filter`; `reports/filter-bar.tsx:34–49` — platform: all.
9. Show ranged-download progress above the report until continuation ends; omit percentages when the total is unknown/nonpositive — partial totals must not look like a genuinely quiet day — evidence: `a40b75cd64 2026-08-06 feat(sync): resumable ranged report fetches with progress — converge past the 10k backstop (#954) (#1023)`; `sync-progress.test.tsx` names the unknown-total and completed-lane cases — platform: all.
10. Give both vertical panels complementary defaults, 40/60 — an unsized second panel can remain a sliver on slow devices — evidence: `82fb564d0a 2026-08-28 fix(pos): size BOTH panels — the unsized cart rendered as a 1.6% sliver on slow devices (#1620)` — platform: all; observed defect originated on Android.
11. On small screens omit the chart and stack Orders/Report; retain bottom safe-area padding — preserves the phone-specific workspace — evidence: `944021c815 2025-04-02 fix screen breakpoints` — platform: all responsive layouts; safe-area protection on native.
12. Delegate column settings to the reactive shared form under `reports-orders` — reset and document updates must reach the rendered column configuration — evidence: `6bbb6a22b4 2026-08-22 refactor(ui-settings): one reactivity model, one column-only form`, body names #1483 — platform: all.
13. Unmount the Sales query workspace in Closures and keep room navigation outside its data suspension; Sales retains its Pro guard — local Closures must remain reachable while Sales loads — evidence: [^closures]; `index.test.tsx` names both unmount/remount and loading-navigation cases — platform: all.
14. Explicitly denied report capability mounts neither room’s readers, but leaves safe-area-aware drawer navigation; unknown capabilities retain access — avoids data reads on denial without stranding the cashier — evidence: [^closures], `reports/index.tsx:243–263` — platform: all.
15. Resolve Free Closures to today and the bound register/current store before readers mount; historical links show the Pro lock without opening historical detail — locking cannot be merely cosmetic — evidence: [^closures], `reports/index.tsx:194–233` — platform: all.
16. Derive the Sales page bar from actual query filters; switching stores resolves the destination timezone immediately, clamps history there, and restores the POS-source sentinel for store zero — avoids misleading scope labels and old-zone date boundaries — evidence: [^closures]; `reports/index.tsx:114`, “A store switch must use the new zone before the query rerenders useStoreDay.” — platform: all.
17. New closure links reset room selection, while consuming a closed link preserves the current room — prevents reopening dismissed details or returning unexpectedly to Sales — evidence: `reports/index.tsx:246`, “Clearing a consumed link keeps the current room; a new link resets its selection.” — platform: all.
18. Seed custom dates from current scope; a multi-day seed starts a fresh two-tap range; enforce retained-history/today bounds and close successful choices — avoids accidentally extending the old range or selecting unavailable history — evidence: [^closures]; `page-bar.test.tsx` names “replaces September 1–30 with September 10–20 using two day taps” — platform: all.
19. Keep picked calendar days as calendar dates across device/store zones; use 44-point days, viewport-bounded picker width, and a separate phone tab row — preserves usable selection on narrow phones — evidence: [^closures]; `calendar.test.tsx` names device-local-midnight conversion; `page-bar.tsx:261`, “Keep the shared day behavior and theme, with touch-sized targets.” — platform: all.
