## Lines

1. Sales initially requests today’s orders on the bound register (Free) and store, every status, with an all-results limit; the status set and cashier are device filters, initially completed + processing and Everyone — evidence: build brief §1 “Filter chips”, §2 “Orders default to completed and processing”; wcpos/roadmap#332 PR 2a; [^query] — platform: all.
2. Re-key the Sales query provider when cashier/store changes, and when the plan changes — validate persisted sorting and otherwise use creation-date descending — prevents retained scope (a Pro-chosen date, store or register after a licence drops to Free) or unsupported settings governing the next report — evidence: [^query], `reports/index.tsx:52–76,164`; test names “re-initializes report filters when the selected store scope changes” and “rejects sort fields outside the orders surface”; the plan in the key from wcpos/monorepo#2238 (Codex review) — platform: all.
3. Resolve default dates in store time; the report always holds a date window — the date button replaces the window, there is no control that clears it (the date pill left with the register and store pills, which would have bypassed the Free lock) — evidence: [^timezone]; `reports/date-button.tsx`; the hero's chips are cashier, status and comparison only (`reports/hero/index.tsx`, wcpos/roadmap#332 PR 2a; the filter bar and its test left with PR 2a) — platform: all.
4. Build report orders from engine payloads and attach the engine UUID for selection — avoids depending on the removed document-proxy representation — evidence: `f11f0b9987 2026-08-20 refactor(core): orders display sweep onto engine-native records (ADR 0028 stage H)` — platform: all.
5. Keep binding, selection and data in separate contexts, with no combined hook — binding-only consumers must not follow every order emission or checkbox change — evidence: `f0534f1075 2026-08-16 perf(reports): split the reports context three ways by change frequency (#1243)` — platform: all.
6. ~~Obtain the stores Suspense resource outside React’s render lifecycle — rebuilding it on an uncommitted retry causes endless suspension~~ — **struck** (wcpos/roadmap#332 PR 1): the store pill and its resource left Reports; the bar reads the stores through `useObservableState` with no Suspense. The rule itself lives on in `hooks/store-list-resource.ts` for the Orders page.
7. Give the cashier chip its own Suspense boundary — an unresolved chip must not blank the route body — evidence: `reports/hero/index.tsx`; wcpos/roadmap#332 PR 2a; carried from `reports/filter-bar.tsx` and #1707 — platform: all.
8. ~~Resolve selected customer/cashier labels through engine lookups and request missing records; do not refresh a guest customer or invalid cashier ID~~ — **struck** (wcpos/roadmap#332 PR 2a): the customer filter is gone; the cashier chip reads display names from the same reactive credentials directory as the bar. Original evidence: [^query]; `73f81fa5fb 2026-04-09 fix: skip guest lookup in reports filter` — platform: all.
9. Original evidence: `82fb564d0a 2026-08-28 fix(pos): size BOTH panels — the unsized cart rendered as a 1.6% sliver on slow devices (#1620)` — platform: all; observed defect originated on Android.
11. On small screens stack the hero (including the unchanged chart), Orders and Report; retain bottom safe-area padding — evidence: build brief §1 “Hero card”; wcpos/roadmap#332 PR 2a, replacing chart omission from `944021c815 2025-04-02 fix screen breakpoints` — platform: all responsive layouts; safe-area protection on native.
12. Delegate column settings to the reactive shared form under `reports-orders` — reset and document updates must reach the rendered column configuration — evidence: `6bbb6a22b4 2026-08-22 refactor(ui-settings): one reactivity model, one column-only form`, body names #1483 — platform: all.
13. Unmount the Sales query workspace in Closures and keep room navigation outside its data suspension — local Closures must remain reachable while Sales loads — evidence: [^closures]; `index.test.tsx` names both unmount/remount and loading-navigation cases — platform: all.
14. Explicitly denied report capability mounts neither room’s readers, but leaves safe-area-aware drawer navigation; unknown capabilities retain access — avoids data reads on denial without stranding the cashier — evidence: [^closures], `reports/index.tsx:243–263` — platform: all.
15. Resolve Free Closures to today and the bound register/current store before readers mount; historical links show the Pro lock without opening historical detail — locking cannot be merely cosmetic — evidence: [^closures], `reports/index.tsx`, `bar.tsx`, `date-button.tsx`; `date-button.test.tsx` names “handles a Free last-closure link for %s in the store day” — platform: all.
16. Derive the Sales page bar from actual query filters; switching stores resolves the destination timezone immediately, clamps history there, and restores the POS-source sentinel for store zero — avoids misleading scope labels and old-zone date boundaries — evidence: [^closures]; `reports/index.tsx:114`, “A store switch must use the new zone before the query rerenders useStoreDay.”; `bar.tsx`, `bar.test.tsx` names “normalises %s–%s before emitting the destination store scope” — platform: all.
17. New closure links reset room selection, while consuming a closed link preserves the current room — prevents reopening dismissed details or returning unexpectedly to Sales — evidence: `reports/index.tsx:246`, “Clearing a consumed link keeps the current room; a new link resets its selection.” — platform: all.
18. Seed custom dates from current scope; a multi-day seed starts a fresh two-tap range; enforce retained-history/today bounds and close successful choices — avoids accidentally extending the old range or selecting unavailable history — evidence: [^closures]; `date-button.test.tsx` names “replaces September 1–30 with September 10–20 using two day taps” — platform: all.
19. Keep picked calendar days as calendar dates across device/store zones; use 44-point days and a viewport-bounded picker width (the phone picker is a sheet whose body scrolls; the room tabs are gone) — preserves usable selection on narrow phones — evidence: [^closures]; `calendar.test.tsx` names device-local-midnight conversion; `date-button.tsx`, `date-button.test.tsx` names “gives custom calendar days at least 44pt targets while retaining the shared theme” — platform: all.

20. Free reaches Sales without a blur or banner: today on the bound register and store renders plainly, and the gate is the lock on the date button and the register/store menu with the hint and one See Pro — evidence: wcpos/roadmap#332 §2 and the build brief (PR 281), this PR — platform: all.

21. The till strip above the Sales body is outside the date: it reads the register session, movements, closures and expected drawer the Closures room reads and reads the server again every minute while the screen is focused and online, keeping what it shows until the answer arrives and retrying after a failure (its result chip is the hook's server-anchored expected, never a second derivation), never the reports query, and is the only way into the Closures room — evidence: build brief §1 “Till strip”; wcpos/roadmap#332; `reports/till-strip.tsx`, `till-strip.test.tsx` — platform: all.

22. Comparison is on by default and only changed: a day against yesterday or the same weekday last week, a week against the week before, a month against the month before, a live day at the same time of day; comparison orders come from a second binding on the same filters with the shifted range — evidence: build brief §2; wcpos/roadmap#332 PR 2a — platform: all.

23. The chart view (by hour/day or running total) is device state for the visit, never in the query — evidence: build brief §2; this PR.
