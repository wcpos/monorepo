Seeded 2026-09-18 from `.claude/research/2026-09-18-composed-behaviour-ledger.md` on `research/composed-ledger` (wcpos/roadmap#341) by wcpos/roadmap#345. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** Arrange extension-provided POS panels and replace only the products content during checkout.

**Composes:** `@wcpos/components/panels`.

## Lines

1. Use one slot-driven layout for both routes, reverse panel order with products position and persist the products panel’s width only after user resizing — route/side changes must not create separate layout behavior or save programmatic sizing — evidence: `a061650537 2026-09-07 feat(pos): one slot-driven columns layout for both POS routes; open-order tabs become the pos.cart.bar slot entry with a top/bottom setting` — platform: all, wide layout.
2. Supply complementary default sizes to both panels and a minimum size — an unsized cart can otherwise remain a roughly 1.5% sliver on slow Android renderers — evidence: `pos-columns.tsx:73–79`, “BOTH panels stay sized”; “products panel next to an unsized cart renders 60:1 — a ~1.5% cart sliver.”; “With both sides sized the fallback IS the” / “correct layout, so the race is harmless.” — platform: all; observed defect on Android.
3. Swap only products content, keep the cart present, key tender by order UUID and prefer the independently selected receipt — two orders must not share a keypad reducer, and a new draft must not displace the paid receipt — evidence: `pos-columns.tsx:98`, “Keyed by order: two orders in checkout must not share one keypad reducer.”; `da7341cd68 2026-09-07 feat(checkout): the tender pane replaces the products column in place; checkout becomes a mode of the order` — platform: all, wide layout.
4. Fade checkout content over 180 ms rather than slide/rise — preserve the motion selected in the prototype ruling — evidence: `pos-columns.tsx:18`, “Ruled on wcpos/roadmap#165 from the prototype comparison (fade vs rise/slide/instant).” — platform: all, wide layout.
5. Give slot consumers stable module-level side snapshots with no notifications during a panel’s mount — a fixed layout side must not create unstable external-store snapshots — evidence: `pos-columns.tsx:27–28`, “A panel's side is fixed for as long as it is mounted, so these views never notify.” / “They are module constants because `useSlotValue` needs a stable snapshot.” — platform: all.
6. Every surface that touches a screen edge owns its safe-area inset inside its own background, and the POS root never pads one: each panel's content (products on `bg-background`, the cart, checkout and receipt on `bg-card`) is an `EdgeColumn` that pads `insets.top`/`insets.bottom` inside its colour, so the columns and the resize handle run the full screen height and the status bar and home indicator float over the column they sit on (Apple: backgrounds edge to edge, content inside the safe area). The phone layouts pad the status bar on the `bg-background` tab container and the home indicator inside the tab bar; the upgrade notice pads the status bar inside its own colour and zeroes the top inset for the stack below it; the desktop title-bar strip (not a system bar) stays on the root — evidence: owner, iPad landscape, 2026-10-14: flat grey bands under the status bar and the home indicator across the full width; `edge-column.tsx`, `pos-columns.test.tsx` — platform: iOS and Android (insets are zero on web; the desktop strip is unchanged).

7. Show the receipt column for the CURRENT order as soon as its stage derives `'receipt'` (a paid checkout member, before confirmation) when receipts show automatically, and keep the same keyed `CheckoutColumn` mounted at receipt stage when they do not — a paid sale must never hand the products column back mid-sale, and the tender's foreground subscriber must stay alive to select or finish — evidence: `pos-columns.tsx` (`receiptUuid`, `showTender`); `pos-columns.test.tsx` 'shows the current paid order its receipt column before any selection' / 'keeps the tender mounted across the paid write when receipts are off' — platform: all, wide layout. _(added 2026-10-23 with the landing PR)_
8. The products column's edge facing the cart keeps no inset: the resize handle is the gutter, one page gutter wide with the grip centred (panels ledger line 5), so the cart's surface (flush with the handle) and the products card sit one page gutter apart, the Gutters table's gap between two content areas; a full gutter on that edge beside an 8 px handle had put nearly two there. The column provides the cart's side as `GroundInnerEdge` (`components/ground.ts`, read by the chip row, the rows, the table surface, the tile ground and the caption inset) and `PageBar innerEdge`, so the whole frame moves as one and follows the cart to either side — evidence: owner, 2026-10-23 ("the spacing between the cart and the products panel needs to be smaller, when on the left and on the right"); `ground.test.ts`, page-bar `index.test.tsx` — platform: desktop and tablet.
