**Job:** Save, enter checkout, void orders and open their metadata editor.

**Composes:** `@wcpos/components/{button,dialog}`.

## Lines

1. Disable and synchronously guard Pay/Save/Void when storage is degraded; recheck after checkout’s awaited save — accepting money or deleting an order without durable local storage loses the transaction record — evidence: `c2660a9776 2026-08-06 feat(pos): degraded storage blocks checkout/save/void with reload CTA (#163 follow-up, ruling R5) (#1019)`; test `storage-degraded-block.test.tsx`: “does not open the payment modal when the worker dies mid-checkout” — platform: all.
2. Enter supported tender checkout immediately, using columns on wide screens and a sheet on phones; legacy/unsupported checkout still awaits saving — the legacy webview lacks the tender flow’s saving gate — evidence: `pos/cart/buttons/pay.tsx:76–78`, “the legacy webview checkout has no such gate”; `c305605f97 2026-09-08 feat(pos): open checkout optimistically while the order saves (#1911)` — platform: all.
3. Re-enter an already-saving checkout without enqueueing another save — repeated Pay presses must reuse the same pending operation — evidence: `36ec3077db 2026-09-08 fix(checkout): follow coalesced writes, keep tender offline while queued, render a refusal`; test `pay.test.tsx`: “re-enters checkout without a second save while saving (%s)” — platform: all.
4. Keep queued-offline checkout open, refuse held orders, and report late rejection without navigating — a delayed refusal must not move a cashier now working on another order — evidence: `pos/cart/buttons/pay.tsx:109–111`, “release this one's checkout and say why, but never navigate”; `559511b990 2026-09-08 feat(pos): report the three order-save outcomes at the tender pane` — platform: all.
5. Convert specifically refused order deletion to an atomic pending-status update — cashiers without delete permission still need a meaningful void; failed enqueue must roll back rather than claim success — evidence: `05529b165b 2026-07-29 fix(pos): void falls back to status=pending when the server refuses order delete`, closes `#864`; `pos/cart/buttons/void.tsx:136–139`, “the shared rollback path unwinds the resident if the enqueue fails” — platform: all.
6. Watch deletion outcomes while connectivity is degraded, skip only truly offline/annihilated writes, and allow one bounded 120-second late watch unless already undone — slow refusals still need conversion without reversing the cashier’s Undo — evidence: `600723d3fe 2026-07-30 fix(pos): harden void outcome watch per review — degraded connectivity, late refusals, atomic fallback`; test `void.test.tsx`: “does not convert on a late refusal after the cashier already undid the void” — platform: all.
7. Restore an existing resident or recreate a deleted order from plain snapshots on Undo, then navigate with an array-valued `orderId` — proxies cannot cross storage messaging, and catch-all routing crashes on a string parameter — evidence: `9eea331b9a 2026-08-23 fix(core): never hand an RxDB proxy to storage — customer create was dead on web`; `c55acc5dbf 2026-04-07 fix: pass orderId as array for catch-all route (#296)` — platform: all; cloning especially web/Electron.
8. Capture the bound register before waiting for void outcome — a register switch during the wait must not stamp the fallback against the new till — evidence: `c7f6319f02 2026-09-12 fix(register): review round on the session PR`; test `void.test.tsx`: “stamps the original register through the real writer when binding switches during the outcome wait” — platform: all.
9. Hold the metadata dialog’s original order independently of current-order selection — sending an order can remove it from open tabs before its editor finishes — evidence: `da8191c571 2026-09-11 feat(pos): overlay batch 6 — order meta owns status, cashier and note; products settings open over the cart (#1991)` — platform: all.
10. Catch a failed delete write, show “Failed to void order” with `LOCAL_DB_WRITE_FAILED`, and return without a success toast or outcome watch — an enqueue failure must not become an unhandled rejection that leaves the cashier without feedback — evidence: `7cea34b339 2026-09-18 fix(pos): voiding an order the server refused removes it locally instead of throwing`, code: `"code: ERROR_CODES.LOCAL_DB_WRITE_FAILED,"` in `packages/core/src/screens/main/pos/cart/buttons/void.tsx:173`; test “surfaces an error toast and no success toast when the delete write fails” — platform: all. _(added 2026-09-18 after seeding by wcpos/roadmap#350: landed 2026-09-18 after the source ledger's read)_
