# Behaviour ledger: `pos/cart/cells`

Seeded 2026-09-18 from `.claude/research/2026-09-18-composed-behaviour-ledger.md` on `research/composed-ledger` (wcpos/roadmap#341) by wcpos/roadmap#345. Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** Render and edit product, fee and shipping rows without losing their display, tax or mutation semantics.

**Composes:** `@wcpos/components/{dialog,error-boundary,hstack,icon,icon-button,image,text,tooltip,vstack}`.

## Lines

1. Forward every remove press to `pulseRemove`, which alone owns re-entrancy through mutation settlement — a second cell latch became permanent when a quantity pulse cancelled removal — evidence: `pos/cart/cells/actions.tsx:31–39`, “One owner for the guard”; `ad2d8f59bd 2026-08-30 fix(pos): drop the cell-level remove latch, leave the guard in pulseRemove` — platform: all.
2. Never express the temporary remove latch through the button’s `disabled` prop — re-enabling could leave Android’s native control latched disabled — evidence: `d4439fcc45 2026-08-30 fix(pos): release the cart remove latch when the removal doesn't land`; test `actions.test.tsx`: “never toggles the button `disabled` prop, which latches on Android” — platform: Android.
3. Log unexpected removal rejection without another toast — the mutation layer already reports handled failures — evidence: `pos/cart/cells/actions.tsx:46–49`, “without a second toast, which would double up on the cashier.” — platform: all.
4. Reduce native quantity-input horizontal padding — two wide digits such as `20` previously painted as `2` despite correct stored/accessibility values — evidence: `f124747c8d 2026-09-09 fix(pos): give the native cart quantity input room for two wide digits` — platform: iOS, Android.
5. Select quantity text on focus — tapping then typing should replace `1` with `3`, not append into `31` — evidence: `5e2b290f4d 2026-09-09 fix(pos): select the native cart quantity on focus so typing replaces it` — platform: iOS, Android.
6. Offer quantity splitting only when enabled in column settings and quantity exceeds one — preserves the optional per-line split action — evidence: `pos/cart/cells/quantity.tsx:46–49` _(inferred — no explicit evidence)_ — platform: all.
7. Ignore negative inline fee values instead of clamping them — merely focusing/blurring a historical negative fee must not silently rewrite it to zero — evidence: `pos/cart/cells/fee-price.tsx:29–32`, “A negative value is therefore IGNORED rather than clamped” — platform: all.
8. Show stock rejection beside the affected product until the server-reported availability is satisfied, scoped to the active order — stale stock needs actionable, self-clearing row feedback — evidence: `pos/cart/cells/product-name.tsx:38–39`, “Highlight lines the server rejected at checkout”; `402c77e68f 2026-07-17 feat(pos): cart stock guard + checkout stock-rejection UX (#724)` — platform: all.
9. Hide underscore-prefixed metadata while rendering public metadata and decoded server-supplied names in edit titles/tooltips — internal POS fields must not leak into product descriptions, and encoded names must remain readable — evidence: `pos/cart/cells/product-name.tsx:55`, “filter out the private meta data”; `pos/cart/cells/edit-cart-item-button.tsx:30–31`, “so both places it renders decode.” — platform: all.
10. Put variation metadata test IDs on the value node, not its separate label — native E2E needs identifier and asserted text on the same node — evidence: `pos/cart/cells/product-name.tsx:103–105`, “id + text must sit on one node” — platform: all; especially native E2E.
11. Strike through regular price only when it differs from price and the on-sale display option is enabled — full-price products must not look discounted — evidence: `b5b46ec0b1 2024-12-27 fix on_sale display for items not on sale` — platform: all.
12. Add tax to displayed subtotal/product/fee/shipping totals only for tax-inclusive cart display; retain optional tax detail — otherwise displayed rows disagree with the store’s selected tax presentation — evidence: `pos/cart/cells/product-total.tsx:30`, “Get display values if cart includes tax”; same comment at `subtotal.tsx:28` and `fee-and-shipping-total.tsx:29` — platform: all.
13. Preserve falsy SKU values and render optional line images only when present, keyed by line UUID — `0`/`false` must not disappear and recycled images need line identity — evidence: `96654eb6ac 2026-03-05 fix: address review feedback from CodeRabbit`; `60e5b2b14e 2026-04-02 feat(cart): add optional line item image column` — platform: all.
