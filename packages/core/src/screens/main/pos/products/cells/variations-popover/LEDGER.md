# Behaviour ledger: `pos/products/cells/variations-popover`

Seeded 2026-09-18 from `.claude/research/2026-09-18-composed-behaviour-ledger.md` on `research/composed-ledger` (wcpos/roadmap#341) by wcpos/roadmap#345. Numbers are assigned once and never reused: a struck line leaves a gap, a new line takes the next number. Every line keeps its evidence. The rules for preserving or striking a line are in the [library strategy](https://github.com/wcpos/roadmap/blob/worktree-docs%2Bdesign-program-2026-09-12/docs/design/2026-09-18-library-strategy.md), section 3. Not reworded from the source.

**Job:** Resolve attribute choices to published variations, stock feedback and an add-to-cart action.

**Composes:** `@wcpos/components/{button,combobox,error-boundary,hstack,icon,select,status-badge,suspense,text,toggle-group,vstack}`.

## Lines

1. Each popover owns a published-only variations query scoped to its parent’s variation IDs — picker state must remain isolated and drafts must not become sellable choices — evidence: `8769a678e3 2026-07-15 feat(core): POS products rides the query-state store + bindings (migration 8/8 — the last screen) (#661)`; `a4518e90ce 2026-07-24 fix(pos): hide non-published products from selling surfaces (#808)` — platform: all.
2. Opening refreshes the parent’s variations once without blocking resident data — locally present children can still be stale — evidence: `8a749dd281 2026-08-05 fix(core): refresh a parent's variations once per picker open (#990)` — platform: all.
3. Empty results trigger two logged retries, spaced three and ten seconds; a fifteen-second unsettled refresh also advances the retry loop — cancelled or hung refreshes previously left unusable “Syncing” popovers indefinitely — evidence: `dc73799ebb 2026-08-31 fix(pos): retry the variation popover's refresh while no variations arrive`; `690f356a0c 2026-08-31 fix(pos): treat a variation refresh that never settles as failed` — platform: all; motivating failures: iOS/Android.
4. Unknown counts remain retryable, but arrivals cancel the need for a scheduled retry; unmount clears subscriptions/timers — neither a silent first emission nor delayed arrivals should defeat bounded recovery — evidence: `a02ba1c16b 2026-08-31 fix(pos): treat an unknown variation count as retryable`; `b660539504 2026-08-31 fix(pos): skip a scheduled variation retry once variations have arrived` — platform: all.
5. “Any option” attributes are matched directly as absent constraints, without materializing combinations — many wildcard attributes previously caused exponential work and browser crashes — evidence: `f75f2e1bc1 2026-01-21 fix: resolve exponential blowup in variations-popover with "any option" attributes` — platform: all.
6. Custom attributes with ID zero match by name; global IDs tolerate missing names — separate custom attributes must not collapse into one identity — evidence: `806e8d5cf7 2026-05-06 Fix variation popover custom attribute matching`; `dc0fcaa854 2026-05-06 fix: handle optional variation attribute names` — platform: all.
7. A sole viable option auto-selects, but wildcard-compatible alternatives remain available — avoids unnecessary taps without choosing an arbitrary “Any” value — evidence: `utils.ts:145`, “Auto-select option if there is only one viable option with a count > 0”; test name: `utils.test.ts`, “should NOT auto-select when "any" variations are present” — platform: all.
8. Option disabling uses the exact Stock Status filter and evaluates alternatives against the remaining partial selection — sellable backorders are not equivalent to `instock`, and `outofstock` must exclude in-stock-only choices — evidence: `2d66ee85af 2026-08-25 fix(pos): variation popover matches the Stock Status pill exactly (#1574)` — platform: all.
9. Short labels use buttons, longer sets use Select or searchable Combobox; displayed labels decode entities without rewriting selection values — preserves compact picking and catalogue identity — evidence: `select.tsx:50`, “Select for short list of options”; `select.tsx:90`, “Combobox for longer list of options”; `select.tsx:67–68`, “Decode the LABEL only — `value` is the identity sent back to onSelect and must stay the catalogue's own string.” — platform: all.
10. Zero matches distinguish active syncing from an unavailable combination — missing data must not look like a permanently impossible selection — evidence: `eff8b5c8e0 2026-05-02 feat(pos): show syncing / unavailable message in variations popover (#358)` — platform: all.
11. The resolved variation displays quantity, backorder or out-of-stock state; sellable unmanaged stock shows no invented quantity — stock news stays visible independently of adding — evidence: `200cff0eaa 2026-07-17 feat(pos): variation stock badge in the variations popover (#719)`; `stock-status.tsx:57–58`, “Renders nothing for a sellable variation with no managed quantity (no numbers when stock isn't managed).” — platform: all.
12. Stock resolves from the child when self-managed, otherwise its managed parent; Add disables on unsellability only when Avoid overselling is enabled — prevents stale inherited child status and permits merchant-authorized overselling — evidence: `849244e34c 2026-09-16 fix(pos): resolve a parent-managed variation's stock from the parent in the popover`; `2c36641673 2026-09-16 fix(pos): variation Add to Cart honours the store's Avoid overselling setting` — platform: all.
13. A pending addition shows loading and rejects re-entry until settlement — the popover remains open during the write, so another press otherwise creates a second cart line — evidence: `b028126e95 2026-09-03 fix(pos): hold the variation popover's Add to cart while an add is pending`, review on #1832; test name: `variations.test.tsx`, “holds Add to cart while an add is pending, so a second press cannot add twice” — platform: all.
