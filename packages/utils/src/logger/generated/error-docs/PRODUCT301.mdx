## What this means {#what-this-means}

No products matched the current search and filters.

Review spaces, category filters, and whether the local product index has finished syncing before searching again.

## What to do {#what-to-do}

Check the details below before trying again. WCPOS does not retry this by itself — retry when you are ready.

## Your data {#your-data}

No order or product data is affected.

## Troubleshoot {#troubleshoot}

1. The scanned code is placed in the search box, so start with the filters: a category or stock filter silently narrows every search.
2. Look the product up by name — if it appears, its barcode field in the store does not contain the scanned value; add the barcode to the product in WP Admin.
3. Check the barcode field in the POS barcode settings — if your store keeps barcodes in a different field, the POS reads the wrong one and every scan misses.
4. If the product is brand new, the local index may still be syncing: give the first sync time to finish, then scan again.

## Where to look {#where-to-look}

Every occurrence of this code is recorded on the device that raised it. Open **Store health → Logs** (the heart-pulse icon at the bottom of the navigation drawer), find the entry marked with this code and expand it: the expanded row shows the plain-language reason and the context captured at the moment of failure — for anything that involved a request to your store this includes the server’s own error code (`serverCode`), the HTTP `status` and the `endpoint`. When reporting a problem, use **Copy debug info** at the top of the Logs screen (**Share debug info** on phones and tablets) rather than screenshots: it bundles the app version, connection state and the most recent errors. Logs are kept for at most 30 days, so collect them while the problem is fresh.
